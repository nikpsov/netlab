# Подбор рабочей стратегии через blockcheckw и blockcheck.sh

У каждого интернет-провайдера установлены свои модификации оборудования ТСПУ и DPI. Стратегия, идеально работающая в Москве на Ростелекоме, может не сработать на МТС в Сибири.

Для автоматического подбора идеальных параметров в состав Zapret входят скрипты автоматического сканирования.

---

## 🔎 Сканеры стратегий

- **`blockcheck.sh`**: Базовый скрипт для Linux и OpenWrt.
- **`blockcheckw`**: Улучшенный сканер для Windows (разработчик `rcd27`).

---

## 🛠 Запуск сканирования на Windows (`blockcheckw`)

1. Скачайте архив `blockcheckw` или используйте его в составе сборки `zapret2`.
2. Запустите файл `blockcheckw.cmd` **от имени Администратора**.
3. Программа начнет автоматический перебор комбинаций (TTL, Fake, Split, Disorder) по списку популярных заблокированных доменов (`googlevideo.com`, `discord.com`, `instagram.com`).

```text
======================================================
SUMMARY OF WORKING STRATEGIES FOR TLS (HTTPS)
======================================================
[+] nfqws --dpi-desync=fake --dpi-desync-ttl=5 -> WORKING
[+] nfqws --dpi-desync=split --dpi-desync-split-pos=2 -> WORKING
```

4. Скопируйте строку с пометкой **`WORKING`** в ваш конфигурационный файл `preset.cmd` / `service_install.cmd`.

---

## 🐧 Запуск сканирования на Linux / OpenWrt (`blockcheck.sh`)

1. Подключитесь к роутеру или серверу по SSH.
2. Перейдите в папку с установленным `zapret` и запустите скрипт:
   ```bash
   /opt/zapret/blockcheck.sh
   ```
3. Выберите уровень проверки (Быстрая или Стандартная).
4. По завершении скрипт выведет итоговую рекомендуемую команду для файла `config`.

---

## 💡 Полезные советы при тестировании

1. **Перед сканированием выключите все VPN и сторонние прокси!** Сканер должен тестировать прямое соединение вашего провайдера.
2. Убедитесь, что ваш компьютере использует **шифрованный DoH/DoT DNS** (см. [Статью 04 о DNS](/docs/zapret-nfqws/04-dns-and-spoofing/)).
3. Если сканер выявил несколько рабочих вариантов, выбирайте тот, у которого меньше значение задержки и нет потерь пакетов.
