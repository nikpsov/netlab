## 🎭 Как Zapret заставляет DPI "проглядеть" заблокированный сайт?

Системы анализа трафика (DPI/ТСПУ) работают под колоссальной нагрузкой: через них каждую секунду проходят террабайты данных. Чтобы не снижать скорость всего интернета, DPI не может глубоко анализировать абсолютно каждый пакет. Он ищет конкретные триггеры в начале сетевого соединения.

Zapret использует тактики **десинхронизации** — создаёт условия, при которых DPI теряет отслеживание TCP-сессии или видит ложные данные.

---

## 🧩 Основные методы десинхронизации

### 1. Фейковые пакеты (`fake`)
- **Как это работает**: Zapret отправляет перед настоящим запросом поддельный пакет (фейк). В этом фейке находится "безопасный" адрес (например, `iana.org`) или мусорные данные.
- **Магия с TTL (Time-To-Live)**: Фейковому пакету задается небольшой срок жизни (TTL). Он успевает долететь до DPI провайдера (который считывает его и думает: *"Ага, тут идут безопасные данные, блокировать не нужно"*), но разваливается в сети и **не долетает до настоящего сервера**. Следом идет настоящий пакет, который открывает сайт.

### 2. Разрезание TCP-сегментов (`split`)
- **Как это работает**: Запрос `GET / HTTP/1.1 Host: blocked.com` разрезается на 2 маленьких пакета:
  - Первый пакет содержит только кусочек: `GET /`
  - Второй пакет содержит остаток: ` HTTP/1.1 Host: blocked.com`
- DPI провайдера видит первый пакет `GET /` без указания домена и пропускает его. Когда приходит второй пакет, логика проверки DPI уже сработала, и блокировка не происходит.

### 3. Изменение порядка пакетов (`disorder`)
- **Как это работает**: Пакеты отправляются в обратном порядке (сначала хвост запроса, потом начало).
- Настоящий сервер (например, сервер YouTube) умеет автоматически собирать пакеты в правильном порядке, а простейшие алгоритмы DPI путаются и теряют контект соединения.

### 4. Изменение регистра заголовков (`hostcase`)
- В стандарте HTTP заголовок пишется как `Host:`.
- Zapret меняет буквы на строчные: `host:`.
- Веб-сервер без проблем понимает `host:`, но старые системы DPI ищут строковое совпадение с заглавной буквы `Host:` и пропускают пакет.

## 🔄 Сводная таблица методов

| Стратегия | Механизм обмана | Когда применяется |
| :--- | :--- | :--- |
| **`fake`** | Ложный пакет с заниженным TTL | Самый мощный метод против ТСПУ (для TLS/HTTPS) |
| **`split`** | Разрезание ClientHello / Host пополам | Для уязвимых к сегментации провайдеров |
| **`disorder`** | Отправка сегментов задом наперёд | Для протоколов TCP при блокировке по SNI |
| **`hostcase`** | Изменение `Host:` на `host:` | Для старых пассивных HTTP DPI |
